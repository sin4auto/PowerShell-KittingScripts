# Windows 11 に Hyper‑V をインストールして仮想マシンを構築する手順

本書は **ISO からの通常インストール（手順3A/4A）** と、**クイック作成での Windows 11 開発者版（手順3B/4B）** の 2 通りを併記します。  
読み手の状況に合うルートを選んでください。

## 前提条件

- **Windows 11 の Pro / Enterprise / Education エディション**であること（**Home エディションでは Hyper‑V を使えません**）
- PC の BIOS/UEFI 設定で、仮想化支援機能（Intel VT-x / AMD-V など）が有効になっていること
- 仮想マシンに割り当てる分のメモリ（この手順では最大 8 GB）と、ディスク容量（同 127 GB）の空きがあること

---

## 手順0：Windows 11 ISO ファイルの入手（手順3A のみ）

仮想マシンにインストールするため、Windows 11 のディスクイメージ（ISO）を Microsoft 公式サイトから取得します。

1. https://www.microsoft.com/ja-jp/software-download/windows11 にアクセス  
2. 「**x64 デバイス用 Windows 11 ディスク イメージ（ISO）をダウンロードする**」までスクロール  
3. 「**Windows 11（x64 デバイス用のマルチエディション ISO）**」を選び「**今すぐダウンロード**」をクリック  
4. 表示言語に「**日本語**」を選び「**確認**」  
5. 「**64 ビット ダウンロード**」をクリック  
6. 保存先とファイル名（`Win11_<バージョン>_Japanese_x64.iso` のような名前。例：`Win11_25H2_Japanese_x64.iso`）を確認して保存

> **メモ**：ダウンロードリンクの有効期間は **24 時間** です。仮想マシン作成時にこの ISO を指定します。

---

## 手順1：Hyper‑V の有効化（インストール）

Hyper‑V は Windows 機能として標準搭載されています。

1. **コントロール パネル**を開く  
2. **プログラムと機能** → 左の **Windows の機能の有効化または無効化**  
3. 一覧から **Hyper‑V** にチェック → **OK**  
4. 指示に従い **再起動**

> 一覧に Hyper‑V が無い場合は、Home エディションの可能性があります（前提条件を参照）。

---

## 手順2：仮想ネットワークの準備（仮想スイッチの作成）

1. 再起動後、**Hyper‑V マネージャー**を起動  
2. 右ペインの **仮想スイッチ マネージャー** をクリック  
3. **新しい仮想ネットワーク スイッチ** → **外部** を選択  
4. **仮想スイッチの作成** をクリック  
5. 名前（例：有線ネットワーク / 無線ネットワーク）を設定  
6. 外部ネットワークに使用中の NIC（例：Realtek PCIe GbE / Intel Ethernet 等）を選択  
7. **OK** をクリックして保存

> **推奨**：Wi‑Fi は不安定になりやすいため、可能なら **有線 LAN** を使用してください。

---

## 手順3A：仮想マシンの作成（通常・ISO から）

1. **新規 > 仮想マシン**  
2. **名前**（例：キッティングテスト機）を設定  
3. **世代**：**第 2 世代**  
4. **メモリ**：**動的メモリを使用する** にチェック  
   - スタートアップ RAM：**4096 MB（4 GB）**  
   - 最大 RAM：**8192 MB（8 GB）**  
5. **ネットワーク**：手順 2 で作成したスイッチを選択  
6. **仮想ハードディスク**：既定値（**127 GB 推奨**）  
7. **インストール オプション**：  
   - 「**ブート イメージ ファイルからオペレーティング システムをインストールする**」を選択  
   - 手順 0 の **ISO** を指定  
8. **完了**（まだ起動しない。続けて **手順 4A** へ）

---

## 手順3B：仮想マシンの作成（**クイック作成**・Windows 11 **開発者版**）

> 開発者向け評価 VM は **クイック作成**から数クリックで用意できます。  
> **注意**：以前の配布ページ（developer.microsoft.com の Windows 仮想マシンのダウンロード）は、現在は別の案内ページに転送されています。そのため、開発者用環境は**入手できない可能性があります**。ギャラリーに表示されない場合は、**手順3A**（ISO から）を使ってください。

1. **Hyper‑V マネージャー**右側の **クイック作成** をクリック  
2. ギャラリーから **Windows 11 開発者用環境（Windows 11 Developer Environment）** を選択  
   - 表示されない場合：ギャラリー更新、管理者で起動し直し、一時的な表示言語の英語化 等で改善することがあります
3. **作成** をクリック（必要に応じて **名前** と **仮想スイッチ** を指定）  
4. 完了後に **接続 → 起動**  
5. 以降は **手順 4B** を参照（OOBE・サインイン・日本語化）

---

## 手順4A：インストールと初期設定（通常・ISO から）

Windows 11 は **TPM 2.0** と **2 コア以上の CPU** を必要とします。Hyper‑V の既定のままでは条件を満たさず、「この PC では Windows 11 を実行できません」と表示されるため、**起動前に**次の設定を行います。

1. Hyper‑V マネージャーで VM を右クリック → **設定**  
2. **セキュリティ**：  
   - **セキュア ブートを有効にする** にチェック（テンプレート：**Microsoft Windows**）  
   - **トラステッド プラットフォーム モジュールを有効にする** にチェック  
3. **プロセッサ**：**仮想プロセッサの数** を **2 以上** に変更  
4. **OK** で保存し、**接続 → 起動**  
5. 「Press any key to boot from CD or DVD...」と表示されたら、**すぐに何かキーを押す**  
   - 間に合わずに起動に失敗した場合は、VM を一度停止して起動し直します
6. Windows 11 のセットアップ画面に従ってインストール  
   - プロダクトキーは「**プロダクト キーがありません**」で進められます（評価・検証用途）
7. OOBE（初期設定画面）を完了してサインイン  
8. **Windows Update** を実行
9. 拡張セッション（クリップボード共有や画面サイズ変更ができる接続方法）を使う場合：**設定 > アカウント > サインイン オプション** の「Windows Hello サインインのみを許可」を **オフ**

## 手順4B：初期設定（クイック作成・**開発者版**）

### 4B‑1：OOBE とサインイン

> クイック作成の VM は Windows 11 が展開済み（英語 UI が多い）です。以下を確認してください。

1. **接続 → 起動** して OOBE を完了  
   - ネットワーク接続の確認（必要なら仮想スイッチを見直し）  
   - Microsoft アカウント / ローカル アカウントでサインイン  
2. **Windows Update** を実行（品質更新と Microsoft Store アプリの更新）
3. **拡張セッションを使う場合**：**設定 > アカウント > サインイン オプション** の  
   「Windows Hello サインインのみを許可」を **オフ**  
4. 以降の **日本語化** は下記「4B‑2」を実施

### 4B‑2：日本語化（GUI）

> **ポイント**：表示言語を日本語にしただけでは、`Start-Admin.bat` などの文字化けは直りません。**この 4B‑2 の 6.（システム ロケールの変更）**まで必ず行ってください。  
> この 4B‑2 の 1.〜3. は英語の画面で操作するため、英語の項目名も併記します。

1. **設定 > 時刻と言語 > 言語と地域** を開く（Settings > Time & language > Language & region）
2. **言語の追加**（Add a language）→ 「**日本語**」 → **次へ**  
   - 「**Windows の表示言語として設定する**」（Set as my Windows display language）にチェック  
   - 音声・手書きなどの追加機能は、必要なものだけ選ぶ → **インストール**
3. インストール後、**サインアウト → サインイン**（画面が日本語になる）  
   - 日本語にならない場合は、「**Windows の表示言語**」で **日本語** を選ぶ
4. **IME**：日本語の **… > 言語のオプション > キーボード** で **Microsoft IME** があることを確認
5. **キーボード配列**：日本語の **… > 言語のオプション** → **ハードウェア キーボード レイアウト** の **レイアウトを変更する** → **日本語キーボード (106/109 キー)**  
   - 「@ を押すと [ が入力される」などのずれは、この設定で直ります
6. **システム ロケール（文字化け対策・必須）**：  
   **言語と地域** の下の **関連設定 > 管理用の言語の設定** → **管理** タブ → **システム ロケールの変更** → **日本語（日本）**  
   - 「**ベータ: ワールドワイド言語サポートで Unicode UTF-8 を使用**」は **オフのまま** にする
7. **ようこそ画面 / 新しいユーザーへ反映（任意）**：  
   同じ **管理** タブの **設定のコピー** → 「**ようこそ画面とシステム アカウント**」と「**新しいユーザー アカウント**」にチェック
8. **タイムゾーン**：**設定 > 時刻と言語 > 日付と時刻** → **(UTC+09:00) 大阪、札幌、東京**
9. **再起動**（この 4B‑2 の 5.〜7. は再起動後に反映されます）
10. **確認**：コマンド プロンプトで `chcp` を実行し、`現在のコード ページ: 932` と表示されれば完了  
    - `437` と表示された場合は、この 4B‑2 の 6. が反映されていません（変更し忘れ、または再起動していない）

---

## 手順5：チェックポイントの作成

初期状態を保存しておくと、何度でも同じ状態に戻せます。

1. セットアップ完了後、VM を **シャットダウン**  
2. Hyper‑V マネージャーで対象 VM を右クリック → **チェックポイント**  
3. 作成された項目の名前を「**初期設定完了_クリーン状態**」などに変更

---

## 手順6：テスト サイクルの実行

チェックポイントを活用して検証を効率化します。

1. チェックポイントから VM を起動  
2. アプリのインストールや設定変更を実施（例：本リポジトリの `Start-Admin.bat` を実行）  
3. 問題があればチェックポイントを **適用** して復元  
4. 必要なテストを繰り返す

## 付録：PowerShell スクリプト実行時のエラー対策（実行ポリシー / エンコーディング）

以下の `スクリプト名.ps1` は、実行したいスクリプトのファイル名に読み替えてください。

### A. 実行ポリシーでブロックされる（UnauthorizedAccess / running scripts is disabled）
```powershell
# 管理者 PowerShell（この PowerShell ウィンドウの中だけ許可する）
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
Unblock-File .\スクリプト名.ps1
```
**グループポリシーで固定されているか確認**
```powershell
Get-ExecutionPolicy -List | Format-Table -AutoSize
```
`MachinePolicy` / `UserPolicy` が設定されていればローカル変更は効きません。管理側に例外（例：RemoteSigned）を相談。

**ポリシーを変えずに 1 行で実行**
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\スクリプト名.ps1
```

> 本リポジトリの `Start-Admin.bat` は、この 1 行実行の形でスクリプトを呼び出しています。

### B. 「The string is missing the terminator: '」等の構文エラー（文字化け）
**原因**：ファイルのエンコーディング不整合（UTF‑8 以外 / スマートクォート混入 等）
**対処：UTF‑8 (BOM 付き) に保存し直す**
```powershell
$path = 'C:\path\to\スクリプト名.ps1'
# -Encoding UTF8 を付けないと、5.1 は BOM のない UTF-8 を Shift-JIS として読み、日本語が化けたまま保存してしまう
(Get-Content $path -Raw -Encoding UTF8) | Set-Content $path -Encoding UTF8  # PowerShell 5.1 は BOM 付きで保存する
```
**スマートクォート混入チェック**
```powershell
Select-String -Path 'C:\path\to\スクリプト名.ps1' -Pattern "[‘’“”]" -AllMatches
```
ヒットしたら `'` と `"` の ASCII に置換。

### C. PowerShell 7（pwsh）で実行（エンコ回避に有効）
```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File 'C:\path\to\スクリプト名.ps1'
```
PowerShell 7 は既定で UTF‑8 を前提とするため、文字化け起因のパースエラーを回避しやすいです。

## まとめ

- Hyper‑V により、Windows 11 の仮想環境を **安定** かつ **柔軟** に構築できます。  
- ISO ルート（3A/4A）とクイック作成ルート（3B/4B）を用意し、**日本語化（GUI）** とスクリプト実行時の **エラー対策** までまとめました。
- **チェックポイント** を使えば、反復作業や検証を **高速かつ安全** に行えます。
